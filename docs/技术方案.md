# AI 漫剧生成网站 · 技术方案

> 版本：v1.0（待确认）
> 日期：2026-08-19
> 状态：技术选型 + 架构方案，确认后进入实现规划

---

## 1. 项目概述

| 维度 | 决策 |
|------|------|
| 产品形态 | **动态漫画 / 有声漫画**（竖屏视频：静态分镜图 + 运镜动效 + 配音 + 配乐，合成导出 MP4） |
| AI 能力 | **全流程**：剧本 → 角色/场景资产 → 分镜 → 关键帧图片 → 视频合成 → 配音 → 配乐 |
| 部署环境 | **国内部署**（需 ICP 备案，使用国内 AI 服务商，遵守 AIGC 内容合规） |
| 目标用户 | **个人自用工具**（单用户，无多租户/计费，架构从简，API Key 自配） |
| 前端框架 | **Next.js**（App Router，TypeScript） |

核心价值：把「一个点子/题材」输入，端到端产出一条可发布的竖屏动态漫画视频。

## 2. 核心技术选型

### 2.1 应用层

| 模块 | 选型 | 说明 |
|------|------|------|
| 前端框架 | Next.js 15（App Router）+ React 19 | 用户指定；RSC + Server Actions 减少 API 样板 |
| 语言 | TypeScript（strict） | 全栈类型安全 |
| 样式 | Tailwind CSS + shadcn/ui | 个人工具以效率优先；视觉遵循 frontend-design 原则做差异化 |
| 状态管理 | Zustand | 编辑器/工作台局部状态，轻量够用 |
| 数据请求 | TanStack Query | 服务端状态缓存 + 进度轮询 |
| 表单/校验 | react-hook-form + zod | 与 Server Actions 共用 zod schema |

### 2.2 服务端 & 数据

| 模块 | 选型 | 说明 |
|------|------|------|
| 运行时 | Node.js 20+（Next.js 内置） | — |
| 数据库 | PostgreSQL 16 | 关系模型天然匹配「项目→集→分镜→镜头」层级 |
| ORM | Prisma | 类型安全、迁移方便，个人项目开发效率高 |
| 任务队列 | BullMQ + Redis | 图片生成、Remotion 渲染均为长任务，需异步 + 进度回调 |
| 对象存储 | 本地磁盘（MVP）→ 阿里云 OSS（上线） | 个人自用先落盘；上公网再迁 OSS |

### 2.3 AI 服务（国内，全流程）

> 原则：**文本用性价比高的国产大模型，图片用带角色参考能力的服务，TTS 优先可自建的开源方案**。

| 环节 | 首选 | 备选 | 选型理由 |
|------|------|------|----------|
| 剧本/分镜/提示词（LLM） | **DeepSeek-V3** | 通义千问 Qwen-Max、豆包 | 中文强、成本低；Qwen 作为复杂剧情兜底 |
| 角色/场景/关键帧图片 | **即梦（Jimeng）** | 可灵（Kling）、通义万相 | 漫画风好、原生「参考图/角色一致性」，国内合规 |
| 图片一致性 | **参考图 + IP-Adapter** | LoRA 微调 | 不训练模型、迭代快（已确认） |
| 配音 TTS | **CosyVoice（本地自建）** | 火山引擎 TTS、MiniMax 语音 | 开源可自建零成本、多音色/音色克隆；火山作云上兜底 |
| 配乐/BGM | **内置 BGM 素材库** | Suno API（若可访问） | 国内无同等 AI 音乐，先素材库 + 手动配，保证合规 |
| 视频合成 | **Remotion** | — | 代码化运镜/字幕/转场，动态漫画主流做法（已确认） |

### 2.4 基础设施

| 模块 | 选型 | 说明 |
|------|------|------|
| 视频渲染 | Remotion `renderMedia()`（本地/单机渲染） | 个人自用不上 Lambda 云渲染；ECS 上跑 headless Chromium |
| 部署 | 阿里云 ECS / 腾讯云 CVM + Docker Compose | Next.js + Postgres + Redis + worker 全容器化 |
| 反向代理 | Nginx / Caddy | HTTPS + 备案域名 |
| 合规 | ICP 备案 + AIGC 内容标识 | 生成内容页脚/水印标注「AI 生成」 |

**分层职责**：
- **UI 层**：项目工作台、分镜编辑器、渲染进度页
- **服务层**：每个 AI 能力一个独立领域服务，统一接口（`generate`/`status`），内部处理供应商差异、重试、限流
- **队列层**：所有长任务（图片生成、TTS、渲染）入队，worker 消费，前端轮询进度
- **渲染服务**：独立 Node worker，Remotion bundle 编译 + Chromium 渲染

## 4. 核心工作流（漫剧生成 Pipeline）

```
① 剧本生成   输入题材/点子 → LLM 生成分集剧本
             （角色表、场景表、分镜描述、台词）

② 资产生成   从剧本拆解角色/场景 → 图片生成角色设定图、场景图
             （首图确立视觉锚点，后续镜头以它为参考图）

③ 分镜生成   LLM 生成分镜表：每镜的画面描述、运镜方式、台词、时长

④ 关键帧    每个镜头 → 图片生成（角色参考图 + IP-Adapter 保证一致性）

⑤ 配音     每句台词 → TTS 生成对应角色音色的音频（CosyVoice 多音色）

⑥ 视频合成  Remotion 把「关键帧 + 运镜 + 字幕 + 配音 + BGM」渲染成竖屏 MP4

⑦ 配乐/导出  选 BGM、混音 → 成片 MP4 预览 + 下载
```

每个环节都**可人工介入**（个人工具的核心）：任一环节 AI 结果不满意，可手动编辑后重跑下游。

## 5. 数据模型（核心表）

```
Project（项目）
  ├─ id, title, 题材描述, 视觉方向, 状态
  └─ Episode（集）*
        ├─ id, projectId, 序号, 剧本JSON
        ├─ Character（角色）*
        │     ├─ id, 名字, 设定描述, 参考图URL, 音色ID
        ├─ Scene（场景）*
        │     └─ id, 名字, 设定描述, 参考图URL
        ├─ Shot（镜头/分镜）*
        │     ├─ id, episodeId, 序号, 画面描述, 运镜类型, 台词, 时长
        │     ├─ 关键帧图片URL
        │     └─ 配音音频URL
        ├─ Music（配乐）*
        │     └─ id, episodeId, BGM路径, 时间点
        └─ RenderJob（渲染任务）*
              └─ id, episodeId, 状态, 进度, 输出MP4URL, 错误
```

关键设计点：
- **剧本存 JSON**（结构化为角色/场景/镜头，而非纯文本），下游各环节从结构化数据驱动
- **Character 持有「参考图URL + 音色ID」**，是跨镜头一致性的锚点
- **RenderJob 独立成表**，记录渲染状态/进度/错误，支撑轮询与重试

## 6. 关键技术难点与对策

| 难点 | 对策 |
|------|------|
| **角色跨镜头一致性** | 角色首图确立视觉锚点 → 每个镜头把「角色参考图 + 场景参考图」传给即梦/IP-Adapter 生成，统一画风 |
| **长任务处理** | BullMQ 队列：生成任务入队 → worker 异步执行 → 前端 `GET /jobs/:id` 轮询进度；渲染失败自动重试 |
| **渲染耗时** | Remotion 单集先渲染成 `concurrency` 分片再合并；个人自用可接受分钟级等待，进度条反馈 |
| **成本控制** | 个人自用：文本用 DeepSeek（廉价）、图片用即梦按量、TTS 用 CosyVoice 自建；已生成资产落盘缓存避免重复计费 |
| **AI 供应商切换** | 服务层统一接口抽象，供应商作为策略实现，切换只改配置不改业务代码 |
| **合规** | 生成内容统一打「AI 生成」水印/标注；个人自用公网访问需 ICP 备案 + 深度合成合规自查 |

## 7. 开发里程碑（MVP 路线）

| 阶段 | 内容 | 产出 |
|------|------|------|
| P0 骨架 | Next.js 初始化、Prisma 建表、基础工作台 UI | 可创建/查看项目与集 |
| P1 剧本 | 接入 LLM，输入题材生成结构化剧本（角色/场景/分镜/台词） | 剧本可生成、可编辑 |
| P2 资产 | 接入即梦图片，生成角色设定图/场景图，确立参考图 | 角色/场景可视资产 |
| P3 关键帧 | 分镜逐镜生成关键帧（参考图一致性） | 每镜有画面 |
| P4 配音 | CosyVoice 自建 + 多音色，逐句合成台词 | 每镜有配音 |
| P5 合成 | Remotion 接入，渲染成竖屏 MP4 | 单集成片可导出 |
| P6 打磨 | BGM 配乐、进度/重试完善、合规标识、Docker 部署 | 可部署自用 |

---

## 8. 风险与待确认项

1. **即梦/可灵 API 的「参考图一致性」具体能力**需在 P2 实测验证（供应商接口细节可能变化）。
2. **CosyVoice 自建**需一张带 GPU 的机器或较新 CPU 做推理；若不便，退化为火山引擎 TTS（按量付费）。
3. **Remotion 服务端渲染**依赖 headless Chromium，需在 ECS 上正确安装依赖（见部署清单）。
4. **视频时长/成本**：单集时长与图片张数、渲染时长直接相关，MVP 先支持「1 集 × 数十镜」规模。
